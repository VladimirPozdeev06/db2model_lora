# Leaderboard — DB2Model

Единая сравнительная таблица (DoD недель 5–6). Все числа — на одном split:
**91 вопрос `bird_large`** по трём базам `financial / toxicology / codebase_community`,
target — **Qwen2.5-Coder-3B-Instruct** (4-bit), один исполнитель SQL, один парсер.

Оси сравнения из плана: **EX** (точность), **VES** (эффективность корректных запросов),
**prompt-токены/запрос** (бюджет контекста — ключевая метрика задачи).

baseline 23.08% = **+4.8 п.п.** при контексте в 3.2 раза меньше (90 vs 288 токенов).
Контроль `zeroshot` 5.49% доказывает, что это заслуга адаптера: `lora − zeroshot` =
**+22 п.п.** чистого вклада обучения. Прирост от объёма данных: lora 16.85 (347) →
27.84 (1171). baseline детерминирован (greedy); lora усреднена по 3 сидам.

- **3 сида на 1171** (0/1/2, `kaggle_seeds.ipynb`): EX 27.47 / 27.47 / 28.57 → 27.84% ± 0.64.
  Ранее публиковавшийся одиночный seed 42 давал 29.67% — выше среднего (наглядно, зачем повторы).
  Разрыв с baseline (+4.8 п.п.) кратно больше σ.
- **VES ≈ EX во всех армах** — корректные предсказания исполняются примерно с той же скоростью,

- **Утечка train→eval** проверена `check_leakage.py`: 2 вопроса (q320, q323) с точным gold-SQL-твином
  в обучении. Без них (3 сида) lora 28.09 ± 1.12 vs baseline 22.47 (89 вопросов) = +5.6 п.п. — знак

## Канонический замер (оценщик напарницы) + ablation учитель/мультизадачи

Все армы, прогнанные через **единый оценщик напарницы** (`evaluate_bird.py` + её
`bird_large_filtered.json`) — чтобы числа были сравнимы между ветками. baseline
консистентен (19.78% в обоих прогонах), значит различия — в lora, не в замере.

| Арм | Учитель / данные | EX | VES | prompt-ток. |
|---|---|---|---|---|
| zeroshot (контроль) | — | 4.40% | 4.12 | 90 |
| baseline (наш) | схема в контексте | 19.78% | 17.58 | 288 |
| baseline (напарницы) | её light-RAG инструмент | 24.18% | 20.60 | — |
| **old_lora** | Qwen-7B, 1171, **без** мультизадач | **27.47%** | 21.15 | 90 |
| new_lora | Qwen-27B, 2699, **с** мультизадачами | 25.27% | 21.15 | 90 |

**Тезис держится:** знание в весах > знание в контексте в обеих версиях
(+7.7 и +5.5 п.п. над нашим baseline при контексте в 3.2× меньше). old_lora (27.47)
обгоняет и baseline напарницы (24.18).

**Отрицательный ablation (честно):** апгрейд «сильный учитель + мультизадачность»
дал **−2.2 п.п.** (27.47 → 25.27). Регрессия целиком на `codebase_community`
(29.6 → 22.2); financial и toxicology идентичны. Две вещи менялись разом (учитель
7B→27B и +мультизадачи), поэтому запущен изолирующий прогон **`qwen27b_sql_only`**
(те же Qwen-27B данные без мультизадач, `kaggle_input_sqlonly/`, train 1096): если
он ≈27+, виновата мультизадачность; если <27 — смена учителя/данных.
