# Leaderboard — DB2Model

Единая сравнительная таблица (DoD недель 5–6). Все числа — на одном split:
**91 вопрос `bird_large`** по трём базам `financial / toxicology / codebase_community`,
target — **Qwen2.5-Coder-3B-Instruct** (4-bit), один исполнитель SQL, один парсер.

Оси сравнения из плана: **EX** (точность), **VES** (эффективность корректных запросов),
**prompt-токены/запрос** (бюджет контекста — ключевая метрика задачи).

**Главный итог: знание в весах обгоняет знание в контексте.** lora (1171) 27.84% ± 0.64 vs
baseline 23.08% = **+4.8 п.п.** при контексте в 3.2 раза меньше (90 vs 288 токенов).
Контроль `zeroshot` 5.49% доказывает, что это заслуга адаптера: `lora − zeroshot` =
**+22 п.п.** чистого вклада обучения. Прирост от объёма данных: lora 16.85 (347) →
27.84 (1171). baseline детерминирован (greedy); lora усреднена по 3 сидам.

- **3 сида на 1171** (0/1/2, `kaggle_seeds.ipynb`): EX 27.47 / 27.47 / 28.57 → 27.84% ± 0.64.
  Ранее публиковавшийся одиночный seed 42 давал 29.67% — выше среднего (наглядно, зачем повторы).
  Разрыв с baseline (+4.8 п.п.) кратно больше σ.
- **VES ≈ EX во всех армах** — корректные предсказания исполняются примерно с той же скоростью,
  что gold, так что эффективность не различает армы, ранжирование по VES то же, что по EX.
  Токены — единственная ось, где lora выигрывает (90 vs 288), но у локальной 3B это почти бесплатно.
- **Утечка train→eval** проверена `check_leakage.py`: 2 вопроса (q320, q323) с точным gold-SQL-твином
  в обучении. Без них (3 сида) lora 28.09 ± 1.12 vs baseline 22.47 (89 вопросов) = +5.6 п.п. — знак
  сохраняется и даже растёт (заученный ответ сработал лишь на одном сиде).
- **light-RAG** — строка ветки напарницы, сводится в конце (общий split уже согласован).
