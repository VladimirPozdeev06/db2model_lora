# Leaderboard — DB2Model

Единая сравнительная таблица (DoD недель 5–6). Все числа — на одном split:
**91 вопрос `bird_large`** по трём базам `financial / toxicology / codebase_community`,
target — **Qwen2.5-Coder-3B-Instruct** (4-bit), один исполнитель SQL, один парсер.

Оси сравнения из плана: **EX** (точность), **VES** (эффективность корректных запросов),
**prompt-токены/запрос** (бюджет контекста — ключевая метрика задачи).

Датасет расширен ×3.4 (347 → 1171 train, см. EXPERIMENTS 18.07). Прогон трёх армов
на Kaggle ждёт запуска. `zeroshot` = 3B без схемы и без адаптера — контроль «выучил
ли адаптер схему»: `lora − zeroshot` = чистый вклад обучения.

- baseline детерминирован (greedy); lora усреднён по 3 сидам: EX 15.38/18.68/16.48,
  VES 15.75/18.40/16.59 (сиды 0/1/2).
- Разрыв baseline − lora = 2.93 п.п. по EX (> 2σ) — реален: схема в контексте пока лучше.
- **VES ≈ EX во всех армах** (баз. 19.84 vs 19.78, lora 16.91 vs 16.85). Значит корректные
  предсказания исполняются примерно с той же скоростью, что gold — эффективность **не**
  различает армы, ранжирование по VES то же, что по EX. Токены — единственная ось, где
  lora выигрывает (91 vs 288), но у локальной 3B это почти бесплатно.
- **light-RAG** — строка ветки напарницы, сводится в конце (общий split уже согласован).

после сведения с веткой light-RAG и снятия VES. Победившая связка оборачивается
в MCP-сервер (см. `src/adv_text2sql/mcp_servers/text2sql_tool/`).

строка light-RAG и финальный выбор — на общем синке.
